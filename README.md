# Ramble to Clarity · 自由口述整理

把自由口述、语音转写或零散笔记整理成清晰的意图摘要，并按需要形成提纲、初稿、决策框架或行动计划。

[English documentation](README.en.md)

## 适合什么场景

你知道很多背景，但还没组织好；你想先随意讲，再让 AI 帮你看清真正的问题；或者你需要在写作、规划和决策前，梳理约束、动机和纠结点。

输入可以是一段文字、多轮聊天或已有的语音转写。无需说满十分钟，也无需准备完整的 prompt。技能本身不负责录音和语音识别。

## 如何处理

| 阶段 | 行为 | 何时进入下一步 |
| --- | --- | --- |
| 接收 | 用户继续说时，简短回应并保留关键背景 | 用户讲完、要求整理或给出明确交付目标 |
| 回放 | 重述目标、动机、约束和未解决的问题 | 足以形成输出，或发现关键缺口 |
| 澄清 | 只追问会改变结果的关键问题 | 问题得到回答，或可以注明假设继续 |
| 交付 | 形成意图摘要、提纲、初稿、决策框架或计划 | 用户核对，并按其纠正更新 |

这是默认处理框架，用户可以直接要求某种产出；不强制每次都走一轮确认。

## 安装

本仓库根目录就是一个技能目录，必需文件只有 `SKILL.md`。在 Codex 中，将整个文件夹命名为 `ramble-to-clarity`，放入个人技能目录：

```text
~/.codex/skills/ramble-to-clarity/SKILL.md
```

如果设置了 `CODEX_HOME`，使用其下的 `skills/ramble-to-clarity`。其他支持技能文件的工具请按各自说明安装；未对每种工具进行兼容性测试。

## 使用示例

**先讲再整理**

```text
$ramble-to-clarity
我会分几段讲，等我说完再整理。
```

讲完后：

```text
说完了。先帮我整理真正想解决的问题、限制和还没想清楚的地方。
```

**写作前整理**

```text
$ramble-to-clarity
下面是我的口述转写。请整理成面向新手的文章提纲，保留我的核心观点，标出待核实的说法。
```

**梳理取舍**

```text
$ramble-to-clarity
我会把几个方案和纠结点说出来。帮我看清取舍，以及还缺哪些会影响选择的信息。
```

若安装环境支持自动选择，类似“我先随便说，你再帮我梳理”的请求也可能触发技能；是否自动触发取决于使用的工具。

## 一个典型结果

输入：“想做个周报，但不想每天填表。我们五个人，老板希望周五看进度，其实最重要的是提前看到卡点。先试两周吧，不想增加大家太多负担。”

整理后可以得到：目标是让五人团队提前暴露阻塞，并在周五汇总进度；约束是减少日常填写负担、试运行两周；仍需澄清现有信息从哪里获取，以及负责人如何收到阻塞提醒。整理过程不会把“周报”直接当成唯一解决方案。

## 来源与限制

灵感来自 [Andrej Karpathy 的 X 原帖](https://x.com/karpathy/status/2079610838143623371)。原帖描述的是个人使用经验；本仓库的四阶段流程、输出字段和检查规则是后续设计，不属于原帖原话。

技能有助于减少表达负担，但输出仍可能误解用户。重要约束和结论需要核对；外部事实的准确性取决于来源和核查条件。本包通过了技能结构校验，尚未进行广泛用户测试。
